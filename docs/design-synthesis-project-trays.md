# Review project trays for corridor screening

In a named project, Design Synthesis can review selected owner ladder-tray records and their assigned project cables as a starting point for corridor screening. Generated proposal trays are not accepted as owner inventory. In **Review existing project trays**, select the trays, provide an inventory and cable-data reference, and confirm coordinate/dimension units, inventory completeness, and permission to consider those paths. Review displays the copied geometry and cable quantities and dimensions. **Replace draft corridors with reviewed trays** changes the synthesis draft only; it does not change the project trays or cables.

Previously generated cables are counted in the tray inventory by default, just like other assigned cables. If previously generated trays, cables, and routes are uninstalled proposal records that the next design will replace, explicitly confirm that in the review to exclude them from the owner inventory. Exclusion requires each record to match a SHA-256 baseline captured when the design was applied; a changed record, ambiguous identity, or missing baseline blocks that review. Designs applied before these baselines were introduced can be reapplied under the existing conflict checks to establish them. Do not exclude assets that are installed or will remain in service. References and confirmations are user-supplied; they do not prove installation status.

Copied edges begin closed. Open each corridor deliberately in the corridor editor before generating. The handoff connects endpoints only when their coordinates match exactly. It does not infer junctions at crossings or join nearly coincident endpoints. The existing-tray screen uses the actual selected tray width and accounts for the reviewed cable inventory. It supports the limited ladder and multiconductor power/lighting scope described in the [capacity-routing guide](design-synthesis-capacity-routing.md#existing-tray-occupancy-screen).

The handoff reads canonical cable raceway assignments, including the `raceway_ids` family of fields. A cable's `allowed_raceways` is a route preference and is not counted as an assignment. If saved route segments through a selected tray disagree with the canonical assignments or refer to an ambiguous cable, review blocks. The user must establish inventory completeness: the application cannot discover unrecorded or unassigned field cables. Each assigned cable needs an explicit recognized size, conductor count, voltage rating, outside diameter, and power/lighting use. If no cable-quantity field is present, one physical cable per record is assumed; the user confirms that basis as part of inventory review. Conflicting aliases or inconsistent alternate tray coordinates block review.

The review binding uses SHA-256 fingerprints of project trays, cable records, and saved routes along with the project and scenario. Before generation, the application rebuilds the review and checks that the source and copied geometry/inventory remain current. Users may change a copied edge's permission and thermal assumptions without changing its reviewed geometry. Source changes, changed geometry, or changed inventory require another review. Drafts with the older review binding must be reviewed again before generation. Input references and user confirmations are retained as supplied, not independently verified.

After generation, a read-only merge preview rechecks the review against the current project, rebuilds tray fill and cable assignments, and identifies the owner trays that would be retained. It flags stale sources or inconsistent route and fill evidence.

To apply a preliminary proposal through reviewed owner trays, provide references for a thermal-interaction assessment and installation suitability and confirm that they cover all selected trays and both existing and proposed cables in the intended configuration. Confirm that generated proposal records are replaceable, review and copy the trays, and enter an explicit ambient temperature, grouped-conductor count, and continuous solid-cover length for each existing tray. Enter zero explicitly where there is no continuous cover. Use **Bind referenced tray reuse basis** after setting the design inputs; changes to those inputs, including the generation baseline, require binding again. Generate and review the proposal before Apply. The application rechecks the current records and reproduces the complete proposal before saving. It retains owner tray and cable records and saves the generated schedules, routes, drawing, and referenced basis in one undoable project transaction.

This remains a preliminary fill, routing, and tabulated-ampacity screen. The application does **not** verify the supplied references or independently calculate existing-cable thermal interaction, tray condition, field clearance, segregation, supports, or grounding. A reference must actually cover the proposed configuration; a generic catalog or example does not establish field suitability. The publicly available scope of [NEMA WC 51/ICEA P-54-440](https://www.nema.org/docs/default-source/standards-document-library/ansi_nema-wc-51_icea-p-54-440-2009-%28r2014%29-contents-and-scope.pdf?sfvrsn=18d924e_2) identifies cable temperatures, loading, and cable depth among tray ampacity considerations; it does not supply installation-specific values for this application. Motor protection and coordination remain separate unresolved requirements.
